## Overview

Not all MCP hosts support Apps. Check the client's `io.modelcontextprotocol/ui` extension and its `mimeTypes` before offering UI-enabled tools. Keep the tool's text result useful when the host cannot render a View.

Core MCP `2025-11-25` sends client capabilities once in `initialize`. Core MCP `2026-07-28` sends them in every request's `_meta`. sunpeak's public HTTP server wrappers currently use the legacy transport. The `oninitialized` example below is for a standalone `McpServer`; sunpeak's wrapper already uses that callback internally. A modern server must read capabilities from each request instead of relying on a connection-level callback.

## getUiCapability

Extracts the MCP Apps capability from the client's `extensions` field.

### Signature

```ts
function getUiCapability(
  clientCapabilities: ClientCapabilities | null | undefined,
): McpUiClientCapabilities | undefined
```

### Returns

<ResponseField name="return" type="McpUiClientCapabilities | undefined">
  The extension settings if the client advertises the key, or `undefined` if it does not. Check
  `mimeTypes` as well before serving HTML.

  <ResponseField name="mimeTypes" type="string[]">
    Supported MIME types. Must include `"text/html;profile=mcp-app"` for MCP Apps support.
  </ResponseField>
</ResponseField>

### Usage

For a standalone legacy `2025-11-25` server instance, use `server.server.oninitialized` to check capabilities after the MCP handshake:

```ts
import {
  getUiCapability,
  registerAppTool,
  RESOURCE_MIME_TYPE,
} from "@modelcontextprotocol/ext-apps/server";

server.server.oninitialized = () => {
  const clientCapabilities = server.server.getClientCapabilities();
  const uiCap = getUiCapability(clientCapabilities);

  if (uiCap?.mimeTypes?.includes(RESOURCE_MIME_TYPE)) {
    // Host supports MCP Apps — register tool with UI
    registerAppTool(
      server,
      "weather",
      {
        description: "Get weather with interactive dashboard",
        _meta: { ui: { resourceUri: "ui://weather/dashboard" } },
      },
      weatherHandler,
    );
  } else {
    // Host does not support MCP Apps — register text-only fallback
    server.registerTool(
      "weather",
      { description: "Get weather information" },
      textWeatherHandler,
    );
  }
};
```

The client capability in the legacy `initialize` request has this shape:

```json
{
  "extensions": {
    "io.modelcontextprotocol/ui": {
      "mimeTypes": ["text/html;profile=mcp-app"]
    }
  }
}
```

## Modern per-request capabilities

Core MCP `2026-07-28` has no `initialize` request or `oninitialized` callback. Each request carries client capabilities at `params._meta["io.modelcontextprotocol/clientCapabilities"]`. A modern server checks the UI extension for the current request before returning UI tool metadata or HTML:

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {
        "extensions": {
          "io.modelcontextprotocol/ui": {
            "mimeTypes": ["text/html;profile=mcp-app"]
          }
        }
      }
    }
  }
}
```

Use the same MIME check on that request's capability object. Do not infer support from a prior request, because modern requests may reach different server instances. For a complete HTTP request and the server's extension advertisement, see [`server/discover` for MCP Apps](/mcp-apps/mcp/server-discover).

## EXTENSION_ID

The extension identifier used in the MCP `extensions` field for capability negotiation.

```ts
const EXTENSION_ID = "io.modelcontextprotocol/ui";
```

Hosts advertise MCP Apps support by including this key in client capabilities. It appears in the [legacy `initialize` handshake](/mcp-apps/mcp/overview#sunpeak-connection-lifecycle) or the modern request metadata described above. `getUiCapability` reads this key from a client capability object.

<Tip>
  The [sunpeak framework](/quickstart) registers its discovered tools and resources through project
  conventions. Its HTTP wrappers currently use the legacy transport and do not branch tool
  registration on the client's UI capability. Return useful text in each tool's `content` so
  clients without a View can still use it.
</Tip>
