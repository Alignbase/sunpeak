<Badge color="green">MCP Apps SDK</Badge>

```ts
import { useApp } from "@modelcontextprotocol/ext-apps/react";
```

## Overview

`useApp` creates an [`App`](/mcp-apps/app/app-class) instance, connects it to the host via `PostMessageTransport`, and returns the connection state. Options are only used on the initial mount — the hook does not reconnect when options change.

## Signature

```ts
function useApp(options: UseAppOptions): AppState
```

## UseAppOptions

<ResponseField name="appInfo" type="{ name: string; version: string }" required>
  App identification sent to the host during `ui/initialize`.
</ResponseField>

<ResponseField name="capabilities" type="McpUiAppCapabilities" default="{}">
  Features this app provides (e.g., `{ tools: { listChanged: true } }`).
</ResponseField>

<ResponseField name="autoResize" type="boolean" default="true">
  Report size changes to the host. See [`App` options](/mcp-apps/app/app-class).
</ResponseField>

<ResponseField name="strict" type="boolean" default="false">
  Throw when host-bound methods run before the initialization handshake completes.
</ResponseField>

<ResponseField name="webMcpBridge" type="boolean" default="true">
  Bridge app tools and WebMCP in both directions. See [WebMCP interoperability](/mcp-apps/app/app-tools#webmcp-interoperability).
</ResponseField>

<ResponseField name="onAppCreated" type="(app: App) => void">
  Called after `App` is created but before `connect()`. Use this to register [event handlers](/mcp-apps/app/event-handlers) that must be in place before the initialization handshake.
</ResponseField>

## AppState

<ResponseField name="app" type="App | null">
  The connected `App` instance, or `null` during initialization.
</ResponseField>

<ResponseField name="isConnected" type="boolean">
  Whether initialization completed successfully.
</ResponseField>

<ResponseField name="error" type="Error | null">
  Connection error if initialization failed, `null` otherwise.
</ResponseField>

## Usage

```tsx
import { useApp } from "@modelcontextprotocol/ext-apps/react";

function MyApp() {
  const { app, isConnected, error } = useApp({
    appInfo: { name: "MyApp", version: "1.0.0" },
    capabilities: {},
    onAppCreated: (app) => {
      app.ontoolinput = (input) => {
        console.log("Tool input:", input);
      };
      app.ontoolresult = (result) => {
        console.log("Tool result:", result);
      };
      app.onhostcontextchanged = (ctx) => {
        console.log("Host context changed:", ctx);
      };
    },
  });

  if (error) return <div>Error: {error.message}</div>;
  if (!isConnected) return <div>Connecting...</div>;

  return <div>Connected to {app?.getHostVersion()?.name}</div>;
}
```

## Behavior

- **Unmount** — The hook closes its `App` when the component unmounts. In React Strict Mode's double mount, and when Fast Refresh re-runs effects, the first `App` closes and a new one connects. The upstream JSDoc still says the `App` is not closed, but the 2.1 code closes it. sunpeak's [`AppProvider`](/app-framework/components/app-provider) keeps one `App` at module scope across both cases.
- **Auto-resize** — The `App` is created with `autoResize: true` by default. Pass `autoResize`, `strict`, or `webMcpBridge` to change the `App` options. For anything else, create the `App` manually and use [`useAutoResize`](/mcp-apps/react/use-auto-resize).
- **Options stability** — Options are only read on initial mount. Changing `appInfo`, `capabilities`, `onAppCreated`, `autoResize`, `strict`, or `webMcpBridge` after mount has no effect.

<Tip>
The [sunpeak framework](/quickstart) provides its own [`useApp`](/app-framework/hooks/use-app) that returns just `App | null` via React context, with additional framework integration.
</Tip>
