## Overview

The `ontoolresult` notification handler is called when the host sends the result of a tool execution. The result includes readable text content, optional model-visible structured data for the UI, component-only `_meta`, and an error flag.

Like all notification handlers, `ontoolresult` should be registered before calling `connect()`.

<Warning>
Register handlers **before** calling `connect()` to avoid missing notifications during the initialization handshake.
</Warning>

## Signature

```ts
app.ontoolresult = (params) => void;
```

## Parameters

<ResponseField name="params" type="CallToolResult">
  Standard MCP tool execution result containing the following fields:
</ResponseField>

<ResponseField name="params.content" type="ContentBlock[]">
  Text content blocks intended for model context.
</ResponseField>

<ResponseField name="params.structuredContent" type="unknown">
  Any JSON value optimized for programmatic use: object, array, string, number, boolean, or null. The model may read this data too, so keep private fields in `_meta`.
</ResponseField>

<ResponseField name="params.isError" type="boolean">
  Whether the tool returned an error. When `true`, `content` contains error details.
</ResponseField>

<ResponseField name="params._meta" type="object">
  Optional metadata attached to the result. MCP 2026 results may include `io.modelcontextprotocol/serverInfo`; servers and hosts may add other fields. Do not assume application fields unless your server sets them.
</ResponseField>

## Usage

### Handling success and error states

```ts
const app = new App({ name: "MyApp", version: "1.0.0" });

app.ontoolresult = (params) => {
  if (params.isError) {
    console.error("Tool failed:", params.content);
    showErrorBanner(params.content);
  } else {
    console.log("Tool output:", params.content);
    console.log("Structured data:", params.structuredContent);
  }
};

await app.connect();
```

### Validate structured content before rendering

```ts
import { z } from "zod";

const TableData = z.object({
  rows: z.array(z.record(z.string(), z.string())),
  columns: z.array(z.string()),
});

app.ontoolresult = (params) => {
  if (params.isError) {
    renderError(params.content);
    return;
  }

  const data = TableData.safeParse(params.structuredContent);

  if (data.success) {
    renderTable(data.data.columns, data.data.rows);
  } else {
    renderTextContent(params.content);
  }
};
```

Do not test `params.structuredContent` by truthiness. `false`, `0`, an empty string, and `null` are valid SDK 2.0 values when the tool's `outputSchema` allows them. Use a schema or check `"structuredContent" in params` when you only need to distinguish an absent field from an explicit value.

### Using with the sunpeak framework

The sunpeak framework provides the [`useToolData`](/app-framework/hooks/use-tool-data) hook, which wraps `ontoolresult` (along with related handlers) into a reactive value for React components.

```ts
import { useToolData } from "sunpeak";

function MyComponent() {
  const { output, isError } = useToolData<unknown, unknown>();
  // output contains structuredContent when the result includes it.
  // isError indicates whether the tool failed.
}
```

See [MCP structuredContent, content, and _meta](/mcp-apps/server/content-structuredcontent-meta) for JSON value support and legacy protocol compatibility.
